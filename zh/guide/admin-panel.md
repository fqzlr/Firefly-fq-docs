# 在线编辑功能指南

Firefly Blog 内置了轻量级在线编辑功能，采用 GitHub App 私钥认证方式，支持在浏览器端直接编辑博客内容，数据通过 GitHub API 提交到仓库，无需数据库，完全免费。

## 功能概述

### 编辑模式特点

- **分布式编辑**：编辑工具栏集成在各个页面，无需跳转到专门的后台
- **草稿暂存**：所有修改先保存为草稿，存在浏览器本地（localStorage）
- **批量提交**：支持多个页面的草稿一次性批量提交到 GitHub
- **安全认证**：使用 GitHub App 私钥认证，私钥仅保存在浏览器本地
- **实时预览**：编辑过程中可实时预览效果

## 访问方式

### 页面内编辑

在支持编辑的页面，顶部或侧边会显示「编辑」按钮，点击即可进入编辑模式。

### 写文章页面

专门的文章写作页面：`/write/`

例如你的博客地址是 `https://example.com`，则写作页地址为 `https://example.com/write/`。

## 认证方式

### GitHub App 私钥认证

本系统使用 **GitHub App 私钥认证**，在浏览器端完成签名，私钥仅保存在本地浏览器：

1. 在 GitHub 上创建一个 GitHub App，并安装到你的博客仓库
2. 为 App 授予仓库 Contents 读写权限
3. 在 App 设置页生成并下载私钥文件（.pem）
4. 在 Vercel/Cloudflare Pages 配置 `PUBLIC_GITHUB_APP_ID` 环境变量（可选，省去输入 App ID）

### 导入私钥

1. 进入任意可编辑页面，点击「编辑」按钮
2. 点击工具栏中的「导入密钥」按钮
3. 选择下载的 `.pem` 私钥文件
4. 系统自动验证私钥有效性

::: tip 安全说明
私钥文件不会上传到博客服务器，仅存储在你当前浏览器的 localStorage 中。清除浏览器数据或点击"清除私钥"后需要重新导入。
:::

## 编辑工作流程

### 基本流程

1. **进入编辑模式**：点击页面上的「编辑」按钮
2. **编辑内容**：修改你想要的内容
3. **保存草稿**：点击「保存草稿」按钮，更改暂存到浏览器本地
4. **继续编辑其他页面**（可选）：可以编辑多个页面，每个页面保存草稿
5. **提交更改**：
   - 单页提交：点击「提交」按钮提交当前页面
   - 批量提交：点击「批量提交」一次性提交所有草稿

### 草稿管理

- **查看草稿**：工具栏显示当前页面草稿数和总草稿数
- **移除单个草稿**：在批量提交弹窗中可移除单个草稿
- **清除全部草稿**：点击「清除全部」按钮清空所有草稿
- **草稿持久化**：草稿保存在浏览器 localStorage 中，关闭浏览器不会丢失

::: warning 注意
草稿仅保存在当前浏览器，换浏览器/设备需要重新编辑。清除浏览器数据会丢失草稿，请及时提交。
:::

### 批量提交

1. 编辑完多个页面后，在任意编辑页面点击「批量提交」
2. 确认待提交的草稿列表
3. 点击「确认提交」按钮
4. 系统将所有更改一次性推送到 GitHub 仓库
5. 提交成功的草稿自动从暂存区移除

## 配置说明

### editConfig.ts 配置

在线编辑的基础配置位于 `src/config/editConfig.ts`：

```typescript
// 友链编辑配置
export const friendsEditConfig: EditConfig = {
  enable: false,        // 是否启用
  fileName: "friends.json",  // 数据文件名
};

// 工具收藏编辑配置
export const collectionsEditConfig: EditConfig = {
  enable: false,
  fileName: "collections.json",
};

// 番剧/影视编辑配置
export const bangumiEditConfig: EditConfig = {
  enable: false,
  fileName: "bangumi.json",
};

// 说说编辑配置
export const momentsEditConfig: EditConfig = {
  enable: false,
  fileName: "moments.json",
};

// GitHub 仓库配置
export const repoConfig = {
  owner: "your-github-username",  // GitHub 用户名
  repo: "your-blog-repo",         // 仓库名
  branch: "master",               // 分支名
  appId: "",                       // GitHub App ID
};
```

### 环境变量

在部署平台配置以下环境变量：

| 变量名 | 说明 | 必填 |
|--------|------|------|
| `PUBLIC_GITHUB_APP_ID` | GitHub App 的 ID | 推荐 |
| `PUBLIC_GITHUB_OWNER` | GitHub 用户名 | 可选 |
| `PUBLIC_GITHUB_REPO` | 仓库名 | 可选 |

::: tip
也可以直接修改 `editConfig.ts` 中的默认值。
:::

- **自动部署**：提交后触发 Vercel/Cloudflare Pages 自动重新部署

## 常见问题

### Q: 导入私钥后提示验证失败？

A: 检查：
1. 私钥文件是否为正确的 .pem 格式
2. `PUBLIC_GITHUB_APP_ID` 是否配置正确
3. GitHub App 是否已安装到目标仓库
4. App 是否拥有仓库 Contents 读写权限

### Q: 提交失败怎么办？

A: 检查：
1. 私钥是否已正确导入
2. GitHub App 权限是否正确（需要 Contents 读写权限）
3. 仓库信息（owner/repo/branch）是否正确
4. 网络是否能正常访问 GitHub API

### Q: 草稿不见了？

A: 草稿保存在浏览器 localStorage 中：
- 清除浏览器数据会丢失草稿
- 换浏览器或设备看不到之前的草稿
- 隐私模式下关闭浏览器会清除草稿

### Q: 可以禁用在线编辑吗？

A: 可以，在 `editConfig.ts` 中将对应模块的 `enable` 设为 `false` 即可。

### Q: 本地开发可以使用在线编辑吗？

A: 可以，但需要正确配置 GitHub App 和私钥，本地提交会真实写入你的 GitHub 仓库。

## 安全建议

1. **妥善保管私钥**：私钥文件不要分享给他人
2. **最小权限原则**：GitHub App 只授予必要的权限
3. **定期轮换密钥**：定期重新生成 GitHub App 私钥
4. **公共设备注意**：在公共设备上使用后记得清除私钥
5. **敏感信息**：不要在编辑内容中输入敏感信息（如密码等）
